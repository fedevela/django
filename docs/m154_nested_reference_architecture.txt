Issue M154: Preserve nested deconstruction paths and reject unstable nested references
====================================================================

## Completion target
- Canonical requirements: M154-001, M154-002, M154-004, M154-006
- Scope: nested class object serialization in field deconstruction, migration serialization, and migration command idempotence.
- Constraint: preserve deterministic structure-only behavior for implementation phase; no runtime policy changes in this artifact.

## Requirement-to-architecture map
- M154-001
  - Owning locus: `django/db/models/fields/__init__.py` `Field.deconstruct()`
  - Boundary: Field model object contract -> migration serialization contract via deconstruct tuple.
  - Structural pressure: preserve nested class `__qualname__` during path construction.
- M154-002
  - Owning locus: `django/db/migrations/serializer.py` `serializer_factory()` + `TypeSerializer.serialize()`
  - Boundary: field option value contract (class object values) -> class-name serializer.
  - Structural pressure: model-local class arguments remain full chain path `<module>.<enclosing>.<nested>`.
- M154-004
  - Owning locus: `django/db/migrations/serializer.py` `TypeSerializer.serialize()` failure path + default `ValueError` in `serializer_factory()`
  - Boundary: class-resolution contract -> existing non-serializable error reporting channel.
  - Structural pressure: never emit invented or shortened paths when stable module/class-chain resolution is not possible.
- M154-006 / Scenario 1 (clean second run)
  - Owning locus: `django/core/management/commands/makemigrations.py` `Command.handle()` and `Command.write_migration_files()`
  - Boundary: migration-change detection -> writer side-effect boundary.
  - Structural pressure: unchanged model definitions must map to `changes == {}` and stay in no-write path.
  - Required invariants: no file writes and no added migration operations for target app.
- M154-006 / Scenario 2 (byte-for-byte stability)
  - Owning locus: `django/db/migrations/writer.py` `MigrationWriter.as_string()` (`OperationWriter.serialize()` participates)
  - Boundary: in-memory migration aggregate -> deterministic text contract.
  - Structural pressure: ordered operation iteration + stable import sorting + template interpolation.
  - Required invariants: regenerated file text is byte-identical for fixed operation/dependency graph and environment ordering.

## Topology and ownership
- Core deconstruction source:
  - `Field.deconstruct()` owns the canonical serialized path seed `(module + __qualname__)`.
  - It is the only module boundary that determines `Field` class identity string.
- Migration serialization sink:
  - `serializer.py` owns conversion from deconstructed path/class values to importable migration code.
  - `_serialize_path()` is the seam for module import prefix handling.
  - `TypeSerializer.serialize()` is the seam for class object options.
- Command execution boundary:
  - `makemigrations.py` owns migration graph comparison and whether filesystem mutations occur.
  - `Command.handle()` owns change/no-change branching.
  - `Command.write_migration_files()` owns migration file creation and persistence.
- Writer boundary:
  - `writer.py` owns the byte-level rendering contract of a `Migration` aggregate.
  - `MigrationWriter.as_string()` and `OperationWriter.serialize()` own operation text and import emission sequencing.
- Error reporting seam:
  - unresolved class chains must flow to existing non-serializable/local-scope reporting through serializer dispatch, not to a synthetic path.

## Dependency direction
- `django/db/models/fields/__init__.py` (Field deconstruction)
  -> produces deconstruct payload consumed by `django/db/migrations/serializer.py`.
- `serializer.py` depends on `models.Field`, `models.manager.BaseManager`, and `Operation` via `serializer_factory()`
  but remains directionally one-way from deconstruct input to emitted migration token strings/imports.
- `django/core/management/commands/makemigrations.py`
  -> consumes `MigrationAutodetector.changes()` and controls whether `MigrationWriter.as_string()` output is materialized.
- `MigrationWriter.as_string()` -> consumes operation list/dependencies and delegates value rendering to `MigrationWriter.serialize()`.
- `TypeSerializer` must not mutate nested class shape; it depends on class metadata attributes (`__module__`, `__qualname__`)
  and existing serializer failure behavior.

## Integration seams / stubs
- Seam S1: `Field.deconstruct()` path string stability
  - Inputs: `self.__class__`
  - Outputs: dotted path with preserved nesting.
  - Invariant: no flattening of inner class segments.
- Seam S2: `_serialize_path(path)` import formatting
  - Inputs: dotted path from deconstruct.
  - Existing shortcut for `django.db.models` remains explicit; nested user-defined suffixes remain untouched.
- Seam S3: class-object dispatch in `serializer_factory()`
  - Must continue to dispatch `isinstance(value, type)` before generic deconstructable fallback for nested class arguments.
- Seam S4: unresolved path reporting
  - Fail closed through existing `ValueError` reporting path.
- Seam S5: no-write branch (second-run idempotence)
  - Inputs: `changes` from autodetector in `Command.handle()`.
  - Decision: empty change map means status-only branch and skip `write_migration_files()`.
  - Output contract: no migration file mutations and no operation rendering side effects.
- Seam S6: deterministic serialization output
  - Inputs: ordered `Migration.operations`, serialized dependency tuples, import token set.
  - Output pipeline:
    1. iterate operations once in stored order
    2. serialize each operation and collect imports
    3. sort imports before render
    4. interpolate migration template with stable key set each call
  - Output contract: same input and environment produce byte-equal migration source.
