Issue #241 + #242 + #243 Media.__add__ and conflict reporting architecture
===============================================================

Issue: MEDIA-001, MEDIA-002, MEDIA-003, MEDIA-004, MEDIA-005
Scope: Global JavaScript media ordering for ``Media.__add__`` merges in
``django.forms.widgets``.

This document expresses structure, ownership, and contracts before code
implementation. No API surface changes are introduced in this phase.


1) Requirement-to-architecture mapping
--------------------------------------

- ``MEDIA-001``
  - Home: ``django/forms/widgets.py`` ``Media._js``
  - Pressure: deterministic global order output for sampled widget media lists while suppressing false-positive conflicts.
- ``MEDIA-002``
  - Home: ``django/forms/widgets.py`` ``Media._js``, ``Media.merge``
  - Pressure: move conflict reporting from pairwise steps to full graph feasibility decision.
- ``MEDIA-003``
  - Home: ``django/forms/widgets.py`` ``Media.__add__``, ``Media._js``
  - Pressure: ensure multi-way merges share a single source of precedence truth.
- ``MEDIA-004``
  - Home: ``django/forms/widgets.py`` ``Media._js``
  - Pressure: warning should be emitted only for true contradictions in the merged constraint graph, and payload should include only files in that contradiction cycle.
  - Observation points:
    - ``tests/forms_tests/tests/test_media_ordering_traceability.py``:
      - ``test_media_004_hard_cycle_a_before_b_and_b_before_a_emits_conflict_warning_spec``
      - ``test_media_004_warning_message_mentions_only_a_js_and_b_js_contradiction_pair_spec``
      - ``test_media_004_cycle_a_before_b_before_c_reports_only_contradictory_files_spec``
- ``MEDIA-005``
  - Home: ``django/forms/widgets.py`` ``Media.merge``, ``Media._js``
  - Pressure: preserve adjacency of each input chunk whenever satisfiable globally.
- ``MEDIA-006``
  - Home: ``django/forms/widgets.py`` ``Media._build_js_constraint_graph``, ``Media._js``
  - Pressure: duplicate JavaScript paths must be represented once in the internal graph and emitted once in output.
  - Observation points:
    - ``tests/forms_tests/tests/test_media_ordering_traceability.py``:
      - ``test_media_006_duplicate_js_paths_appear_once_during_merge_contract``
- ``MEDIA-007``
  - Home: ``django/forms/widgets.py`` ``Media.__add__``, ``Media._js``, ``Media.merge``
  - Pressure: maintain legacy-compatible two-object ordering semantics when no true contradiction exists.
  - Observation points:
    - ``tests/forms_tests/tests/test_media_ordering_traceability.py``:
      - ``test_media_007_two_object_merge_backwards_compat_without_false_positive_blocker_contract``
- ``MEDIA-008``
  - Home: ``django/forms/widgets.py`` ``Media._build_js_constraint_graph``, ``Media._resolve_js_order``, ``Media._discover_js_cycle``
  - Pressure: equivalent merge graphs and grouping must produce deterministic JS order and warning payload.
  - Observation points:
    - ``tests/forms_tests/tests/test_media_ordering_traceability.py``:
      - ``test_media_008_equivalent_merge_grouping_determinism_contract``


2) Module and file placement
-----------------------------

- **Primary owner**: ``django/forms/widgets.py``; no additional modules required for current issue.
- **Core container**: ``Media`` class owns all media-ordering state and behavior:
  - ordering state: ``_js_lists`` (chunk-provenance list)
  - public materialization points: ``_js`` property and ``__getitem__``
- **Verification surface**: ``tests/forms_tests/tests/test_media_ordering_traceability.py`` remains canonical for scenario IDs and acceptance mapping.
- **Architecture helper seams (future implementation scaffold):**
  - private boundary in ``Media``:
    - ``_build_js_constraint_graph(self, chunks)``
    - ``_resolve_js_order(nodes, edges, node_position)``
    - ``_discover_js_cycle(unresolved_nodes, edges, node_position)``
  - These helpers are contract points for deterministic extraction and cycle-only payload selection.


3) Boundaries and ownership
---------------------------

- ``Media.__add__``
  - Ownership: chunk provenance assembly.
  - Responsibility: preserve input chunk boundaries by concatenating ``_js_lists`` and ``_css_lists``; it must **not** decide final merge conflicts.

- ``Media.merge``
  - Ownership: local candidate merge operations between two lists.
  - Responsibility: build/merge adjacency edges without concluding conflict decisions.
  - Constraint behavior: should emit local edges for each adjacent pair; conflict state is deferred.
  - MEDIA-004 pressure: do not construct warning payload from this local path.
- ``MEDIA-006``: dedupe policy must live in graph materialization, not in rendering-time post-filters.

- ``Media._build_js_constraint_graph``
  - Ownership: canonical node identity and edge extraction from chunk input.
  - Responsibility: normalize duplicate paths to one node while preserving first-seen index metadata.
  - Boundary: no warning emission or output formatting should occur here.
  - Pressure mapping:
    - ``MEDIA-006``: repeated path in any chunk is reduced to a single node.
    - ``MEDIA-008``: node order hints must be deterministic across equivalent chunk groupings.

- ``Media._resolve_js_order``
  - Ownership: deterministic global order candidate selection.
  - Responsibility: stable topological ordering using deterministic tie-breakers derived from node_position.
  - Boundary: ordering must be deterministic independent of insertion/collection path shape.
  - Pressure mapping:
    - ``MEDIA-007``: valid two-object outcomes preserve legacy order where no global contradiction exists.
    - ``MEDIA-008``: identical graphs collapse to identical node processing sequences.

- ``Media._discover_js_cycle``
  - Ownership: deterministic contradiction witness extraction.
  - Responsibility: return one ordered representative cycle for warning reporting on unresolved graphs.
  - Boundary: traversal ordering must be deterministic to stabilize warning payload under associativity permutations.
  - Pressure mapping:
    - ``MEDIA-008``: equivalent graph structure always generates same cycle node order.
    - ``MEDIA-007``: warning only when no satisfiable global resolution exists.

- ``Media._js``
  - Ownership: final global constraint resolution.
  - Responsibility: collect all chunk constraints from ``_js_lists`` and solve global ordering.
  - Responsibility boundary: this is the single place to emit ``MediaOrderConflictWarning``.
  - MEDIA-004 pressure: warning payload must be derived from contradiction cycle extracted from the merged graph; exclude transient intermediate pairwise artifacts.
  - ``MEDIA-006``: output list comes from resolved node order; duplicates are eliminated by node identity.
  - ``MEDIA-008``: warning and output contracts must be deterministic for equivalent graphs.

- ``media_property``
  - Boundary: stable external seam that combines class/widget media trees via ``Media`` arithmetic.
  - No ordering logic changes expected.


4) Contracts and interfaces
----------------------------

- ``MediaOrderConflictWarning``
  - Input contract: raised when global adjacency graph is cyclic.
  - Output contract: one warning per unresolved object materialization path where total order is impossible.
  - MEDIA-004 extension:
    - include file refs from a real contradiction cycle only,
    - avoid listing unrelated or pairwise-intermediate nodes.

- ``Media._js`` contract (deterministic)
  - Input: ordered chunk list ``self._js_lists``.
  - Invariant: each input chunk preserves adjacency edges ``x_i -> x_{i+1}``.
  - Output: total list that is topologically valid for all edges, or conflict fallback path with warning.
  - Conflict contract for MEDIA-004:
    - on unresolved nodes, extract one concrete cycle subgraph and emit cycle-participant files only.

- ``Media.merge(list_1, list_2)``
  - Input: two ordered media lists.
  - Invariant: no early contradiction finalization; adjacency edges can be suggested/accumulated but only used by ``_js`` for global evaluation.
  - Output contract for MEDIA-004: emits deterministic order-only merge result when used as local fallback.

- ``Media.__add__(self, other)``
  - Input: two ``Media`` objects.
  - Output: new ``Media`` whose chunk vectors are concatenations of inputs.


5) Dependency direction
-----------------------

``media_property`` -> ``Media.__add__`` -> ``Media._js_lists`` -> ``Media._js`` -> ``render_js``.

``Media.merge`` remains helper-only; warning and full feasibility checks are consumed by ``Media._js`` only.


6) Integration seams for implementation
--------------------------------------

- Merge-time seam: ``Media.__add__`` must remain the only place that aggregates chunk provenance.
- Resolution-time seam: ``Media._js`` is the only finalizer and conflict-warning boundary.
- Observation seam: traceability map in ``tests/forms_tests/tests/test_media_ordering_traceability.py`` links ``MEDIA-*`` IDs to scenario contracts and remains stable for implementation verification.


7) Minimal scaffolding needed later
-----------------------------------

- Internal helper(s) to materialize adjacency constraints from all chunks (can stay inside ``Media``, private scope).
- Topological ordering utility inside ``Media._js`` path; warning emission remains in ``Media._js``.
- Optional private helper for stable output de-duplication under a fixed topological order.
 - Deterministic tie-break helpers based on first-seen node index for both ordering and cycle discovery.
