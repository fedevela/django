Issue DJANGO11099 — Username validator boundary anchors
=====================================================

This artifact records where the deterministic logic for
``DJANGO11099-001`` … ``DJANGO11099-007`` should live at the
architecture level before implementation changes.

Requirement-to-architecture map
------------------------------

1. ``DJANGO11099-001``
   - **Obligation type:** boundary/canonical contract enforcement
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``ASCIIUsernameValidator.regex``
   - **Placement:** class-level attribute in ``ASCIIUsernameValidator``
   - **Boundary:** class boundary to downstream ``RegexValidator`` match
     semantics.
   - **Acceptance impact:** value must fail when not an exact-string match.

2. ``DJANGO11099-002``
   - **Obligation type:** boundary/canonical contract enforcement
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``UnicodeUsernameValidator.regex``
   - **Placement:** class-level attribute in ``UnicodeUsernameValidator``
   - **Boundary:** class boundary to downstream ``RegexValidator`` match
     semantics.
   - **Acceptance impact:** value must fail when not an exact-string match.

3. ``DJANGO11099-003``
   - **Obligation type:** behavior-seam: boundary rejection path
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``ASCIIUsernameValidator`` invocation chain
   - **Placement:** runtime boundary is the `ASCIIUsernameValidator` class
     configured for string-only matching.
   - **Boundary:** input-validation seam at ``v("alice\\n")`` call.
   - **Acceptance impact:** explicit failing path for trailing newline.

4. ``DJANGO11099-004``
   - **Obligation type:** behavior-seam: boundary rejection path
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``UnicodeUsernameValidator`` invocation chain
   - **Placement:** runtime boundary is the `UnicodeUsernameValidator` class
     configured for string-only matching.
   - **Boundary:** input-validation seam at ``v("alice\\n")`` call.
   - **Acceptance impact:** explicit failing path for trailing newline.

5. ``DJANGO11099-005``
   - **Obligation type:** contract-semantics preservation
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``ASCIIUsernameValidator.regex`` and ``UnicodeUsernameValidator.regex``
   - **Placement:** class-level regex contracts remain unchanged and remain the
     gate for canonical allowed-character validation.
   - **Boundary:** positive path through full-string regex match for inputs such
     as ``alice``, ``alice.+-@bob``, ``user.name+tag-2``.
   - **Acceptance impact:** both validators must continue to accept the allowed
     character set without introducing behavior drift.

6. ``DJANGO11099-006``
   - **Obligation type:** non-empty invariant preservation
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``ASCIIUsernameValidator`` and ``UnicodeUsernameValidator``
   - **Placement:** regex contract at class boundaries via ``+`` quantifier.
   - **Boundary:** empty-string input remains outside the allowed match shape and
     returns validation failure at `RegexValidator.validate` seam.
   - **Acceptance impact:** ``""`` remains invalid for both validators.

7. ``DJANGO11099-007``
   - **Obligation type:** disallowed-character failure preservation
   - **Owner:** ``django/contrib/auth/validators.py`` →
     ``ASCIIUsernameValidator`` and ``UnicodeUsernameValidator``
   - **Placement:** character-class boundary enforced by ``[\w.@+-]``.
   - **Boundary:** values containing whitespace or punctuation (for example
     ``alice name``, ``alice!``) do not satisfy full-string match and fail at the
     same seam as other boundary mismatches.
   - **Acceptance impact:** disallowed characters keep raising
     `ValidationError`.

Topology and ownership
----------------------

- **Domain boundary:** `django.contrib.auth.validators` owns username input
  validation shape for both ASCII and Unicode variants.
- **Class boundary:** each class expresses a specific contract through three
  class attributes:
  - ``regex``
  - ``message``
  - ``flags``
- **Stable contract boundary:** both classes remain subclasses of
  ``django.core.validators.RegexValidator``; callers continue to depend on the
  same public behavior.

Dependency-direction notes
-------------------------

- ``validators.py`` depends on:
  1. ``re`` (local regex pattern flags).
  2. ``django.core.validators`` (base validation flow).
  3. ``django.utils.translation.gettext_lazy`` (error message i18n).
- Validation usage in tests depends on:
  1. ``django.contrib.auth.validators`` public exports.
  2. ``ValidationError`` exception contract from ``django.core.exceptions``.

- Requirement tracking path for these obligations:
  1. ``tests/auth_tests/test_validators.py`` owns the traceability map
     ``USERNAME_VALIDATOR_REQUIREMENT_TO_TEST``.
  2. ``UsernameValidatorContractTests`` provides boundary behavior stubs for all
     active issue IDs and is the seam where validation contracts remain
     observable.

Integration-seam skeleton
-------------------------

- **Regex-anchor seam:** replace boundary tokens in
  ``ASCIIUsernameValidator.regex`` and ``UnicodeUsernameValidator.regex``
  with explicit string-boundary anchors.
- **Behavior-seam verification skeleton:** maintain/extend
  ``tests/auth_tests/test_validators.py`` with issue-specific tests:
  ``test_django11099_001_*`` through ``test_django11099_007_*``.
- **No cross-module changes:** do not route through password validators or other
  auth validation components.

- **Structural placeholders:** preserve the non-empty/disallowed-path contracts via
  explicit placeholder assertion scaffolding in:
  ``test_django11099_005_non_empty_allowed_usernames_preserve_acceptance_for_ascii_and_unicode_validators``,
  ``test_django11099_006_empty_usernames_remain_invalid_for_ascii_and_unicode_validators``,
  ``test_django11099_007_disallowed_characters_remain_invalid_for_ascii_and_unicode_validators``.
